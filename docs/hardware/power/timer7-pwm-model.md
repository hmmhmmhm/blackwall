# TIMER7 PWM Candidate Model and Original Initial Configuration

Work `bw-0233`. Channels 0/7/14 were handled by one existing common engine under the [original contract](timer7-pwm-contract.md). No physical access, flash, OTA, or permanent write occurred.

## Implementation scope

`timer7Profile="nominal-hfrc96-pwm"` in `renode-timer14.cs` is optional. Default `none` continues blocking TIMER7 access. The profile is used **with the PWM candidate engine generated by `timer14_engine_source.py --timer7-pwm`**. Default engine generated bytes match previous SHA `cb7f473751566fa8f72009385d7dc01c24b35da39174cf10ef6004f37718f965`. Candidate engine is not retroactively injected into past runs.

The candidate retains counter at PWM comparator 1 and resets it to 0 only at comparator 0. Reset explicitly sets channel 7 clock to nominal 96 MHz/4 because the initial selector is 0 and a change callback alone cannot apply that frequency. Existing channel 0/14 behavior remains. Comparator events and IRQ masks are distinct; TIMER7 IRQ is 74, shared interrupt bits 14/15.

The adapter handles CTRL7 `0x40..0x43`, trigger-disabled MODE `0x100`, held CLR, stop, restart, and GLOBEN gate. Start/gate return is allowed only for period>0, low phase>0 and below period, counter<period. Default initialization's `0xffffffff` comparator values can be stored while stopped. Period/duty changes while running, 0/100% duty, other clocks/functions/triggers are unsupported. Unsupported requests are not treated as successful.

GPIO145 OUTCFG36 is owned by the adapter as a separate latch. Word reset is `0x3f3f3f3f` from public register documentation; only GPIO145 selector 14 or disabled 63 is supported. Writes changing other pads/reserved bits are rejected. `Timer7Output0/1` are **logical phases sampled** from counter. GPIO mux, pin electrical signals, and external delivery of output edges are not modeled. Physical clock-source error, power domain, and synchronization delay were not verified either.

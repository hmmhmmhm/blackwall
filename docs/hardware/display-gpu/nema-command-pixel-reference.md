# Limited pixel reference from original command lists

bw-0257. Saved Renode M55 original command lists were read to **place the letter A on a 64×32 reference image**. Glyph crops for three firmware images match byte-for-byte against newly executed original ARM font bitmap callbacks. This image is neither GPU execution output nor main's framebuffer.

## Confirmed evidence and remaining assumptions

Three Nema label/image/utils C files from pinned LVGL `cff1c632206a267534102ee1065f51ac87be4099` were obtained. Git blob, SHA256, and MIT notice were verified and recorded in private `nema-pixel-contract-research-01/source-manifest.json`.

- [Format-conversion source](https://github.com/lvgl/lvgl/blob/cff1c632206a267534102ee1065f51ac87be4099/src/draw/nema_gfx/lv_draw_nema_gfx_utils.c) maps LVGL A4→NEMA_A4, L8→NEMA_L8, NORMAL blend→NEMA_BL_SIMPLE.
- [Label source](https://github.com/lvgl/lvgl/blob/cff1c632206a267534102ee1065f51ac87be4099/src/draw/nema_gfx/lv_draw_nema_gfx_label.c) connects raw bitmap, glyph box, source texture, matrix, and raster rect. This version also flattens some raw glyphs into one row. G2 original's observed per-row stride was not replaced by this implementation.
- Actual G2 original bitmap callback reads packed source high nibble first and expands 0..15 to 0..255. That callback was rerun here and output compared.

GPU A4 sampler, L8 channel conversion, clip endpoints, integer rounding, and built-in CODEPTR meaning were not verified on physical hardware or a vendor runner. These are explicitly recorded as reference-profile assumptions.

## Implementation scope

`render_white_a4_reference` in `nema_pixel_reference.py` checks even the order of 42 command words. It accepts only white `0xffffffff`, ROP `0x504`, CODEPTR `0x141f801f`, A4 source, zero-filled L8 destination, matching integer translation, and 64×32 surface. Output stride is 64/80. Apart from caller-provided source reads, it does not directly read/write MMIO or guest memory.

Unsupported shader, blend, color, matrix, format, command order, clip bounds, or nonzero destination are rejected before reading source. This code cannot complete arbitrary GPU commands. No connection to actual GPU model or completion IRQ was added.

`render_nema_reference.py` requires explicit profile selection. After checking native input/final RAM hashes, canonical Nema area, original bundle/main hashes, and command words, it reads source only from original ROM range. Original guest surface is unchanged; a **separate derived image** is created.

## Results and controls

Existing M55 batches for stock 2.4, stock 2.3, and Faceclaw38 were reused. No new native runs. Original descriptor and bitmap callbacks were executed for each image on an auxiliary M7 engine, six calls total, with synthetic arguments/caller buffers. Original code/branches/returns were unchanged; no observer hooks. Read-only SRAM, output-buffer canaries, final memory-change range, and ABI were checked.

All three use draw=`[10,16,21,32]`, clip=`[0,0,64,32]`. The 11×16=176-byte A crop matched original callback and the earlier bitmap audit hash:

```text
e6e7bf735daca22bc0e759f331ba48d9c1aa9ce05d3df9e4a157854e76772c56
```

**This actual A asset contains only 0/255.** Thus it cannot establish GPU rounding at intermediate alpha. A separate synthetic 16-level alpha test verifies only nibble handling in reference code.

- Seven unit tests: all 16 alpha levels, source row padding, source coordinates after clip, output stride 80, unsupported settings rejection, nonzero destination/truncated list/truncated source rejection.
- 107 saved-audit checks: actual command RAM, input/final hashes, decoded PNG pixels, crop, zeros outside glyph, unchanged original guest surface, public source blob/license.
- Python compile passed. All 32 rows and letter position were visually checked in a three-image comparison enlarged 8× nearest-neighbor.

After initial run 01, native SRAM/snapshot hash preflight was strengthened and 02 run. Six original callbacks were rechecked; BIN/PNG results of both runs match. Initial unit red was import failure due to unimplemented module, not GPU behavior red.

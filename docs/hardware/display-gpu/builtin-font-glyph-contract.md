# Original glyph lookup contract for embedded fonts

## Confirmed scope

Work bw-0218 identifies character coverage of fonts already embedded in original main without substituting for external XIP fonts. Five nonnull descriptors were confirmed in each of stock 2.4.0.24, 2.3.0.24, and Faceclaw 38. All declared glyphs, boundaries, missing and representative character inputs were compared using original ARM callback.

Character coverage was identical across three images. The union of five fonts contains all 95 printable ASCII characters, plus Greek, Cyrillic, and some emoji. Interpreted character maps contain no glyphs in Hangul syllables U+AC00–D7A3, CJK U+3400–9FFF, or U+20000–323AF. This is not a claim of absence across every language or Unicode range.

This is descriptor lookup evidence. Original font-chain traversal, bitmap extraction/release, rasterization, main framebuffer, and actual panel output were not verified. It does not establish initial-screen success without external fonts. Null-descriptor restriction in [external font failure path](xip-font-resource-contract.md) remains.

## Original main memory capture

`tools/probe_builtin_font_memory.py` ran three original mains under the same conditions as existing `timer0-shared-main-02/*-low`. Only after CPU stopped at first `0x80100000` XIP guard did it read virtual SRAM `0x20000000–0x20005fff`. This range includes observed embedded/external font objects and two configuration tables. It is not an actual device dump; memory was generated by original ARM code and existing synthetic peripheral state.

No new CPU hooks, guest writes, or XIP responses were added. CPU/device reports including instruction count and all existing observed events exactly matched previous runs. The +1 count difference from earlier bw217 instruction-hook observation is absent in this method. Code, board, and memory input hashes were verified before/after.

Results outside Git: `simulator/builtin-font-memory-main-01/{stock24,stock23,cfw}/`. Each `low-sram.bin` is 24,576 bytes with hash in `report.json`. Proprietary main and initialized memory are not added to Git.

## Character maps versus original callback

`tools/inspect_builtin_font_glyphs.py` rechecks native input hashes, logs, and memory hashes and compares each object's 36 bytes to RAM copy. Descriptor, cmap, sparse/offset lists are read only within pinned main ROM range. Character-map format is based on 20-byte descriptor and 20-byte cmap entries confirmed in original disassembly, not structure layout from another installed LVGL version.

Independent map interpretation is not substituted for original firmware functions. Actual callback is called in Unicorn and success and returned glyph ID (+`0x18`) compared. Inputs cover all declared glyphs, each cmap endpoint and adjacent points, deterministic intermediate inputs, and representative ASCII, Greek, Cyrillic, Hangul, Han characters, emoji, NUL, tab, and others. Not every missing Unicode input was exhaustively run. Original callback treats tab as space, and that rule is also compared.

Original main is mapped read/execute; original low SRAM copy restored on each call. Output, stack, return boundary, and function arguments are synthetic. Opcodes, internal branches, function returns, and MMIO are not replaced. Normal return and SP/callee-saved register preservation are checked each call. This standalone entry is not reported as natural full-main display path.

Declared glyph counts do not mean font names or full language support. Glyphs overlap among the five fonts, so their counts are not summed as distinct characters.

## Implications for development

There is now evidence to reuse main-embedded assets for small ASCII-only display experiments. This does not justify manipulating external font headers or skipping original initialization. An external font appears before the shared final font, so conditions under which actual chain encounters a descriptor-null object also need separate confirmation.

Continue investigating official distribution, version, hash, and pointer contracts of external font-bank for an integrated simulator with normal stock assets. Next execution extension must distinguish actual assets from explicit missing-asset diagnosis. Bitmap callback input/output and buffer ownership remain to be identified. Full main boot, 576×288 output, and web-integrated installation success are incomplete. Overall progress remains 13/29, 44.8%.

Follow-up bw240: [bitmap conversion contract](builtin-font-bitmap-contract.md) executed original ARM callback and actual initialized stride handler to obtain A8 pixels of representative glyphs. This is standalone function testing; the integrated main/display incomplete judgment above remains.

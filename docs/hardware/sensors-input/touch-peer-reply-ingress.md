# From touch peer replies to original application state

bw444. **Stock 2.4 original main reset → GPIO27/IRQ56 → input task → UART0 transmit → virtual peer reply via UART0 RX → original parser/ID matching → registered worker callback → state change and return to original caller** was confirmed. The host did not directly call parser/callback or write pending records, TCB, or branches.

This connects the E11 application-consumption boundary on one supported image. Natural screen changes, the same integrated path on stock 2.3/Faceclaw, and gesture/ring scope remain incomplete. Overall **10/16=62.5%** and API screen checklist 3/6 remain.

## Evidence for virtual peer replies

Follow-up [bw445](touch-family-app-and-idle-routing.md) confirmed stock 2.3/Faceclaw integration and stock 2.4 idle-scroll discard. The scope below is as of bw444.

The last two actual UART transmissions from [bw443](touch-app-consumer-contract.md) were used as inputs. Original registered channel 1 listener `0x466af8` checks upper type 9 of a request packet and constructs a reply descriptor beginning with byte `0x0a`, preserving the request ID.

Original listener through reply encoder executed as **isolated M7 ARM**, stopping immediately before transport function entry. Actual 12-byte frames generated by the original were:

| Original request | Original encoder reply |
| --- | --- |
| `0x800a / 0x107` | `01800a00010000c1c60a0780` |
| `0x800b / 0x108` | `01800b0001000001fb0a0780` |

Reply channel is 0. Request channel 1 or channel 2 from earlier display tests was not copied. The other temple's full main was not executed; descriptor and function caller are synthetic isolated-test inputs. Actual source image, current context, and original request contents were preserved; internal firmware callees were not stubbed.

## Natural M55 integration input

GPIO input uses the existing explicit pulse profile. High was supplied 1 ms after falling and the whole machine paused at 5 ms. After confirming 12 original UART DMA completions and the last two original requests, two replies in the format above, 24 bytes total, were inserted into UART0's optional RX FIFO.

The existing runtime's frozen UART adapter lacked an RX option. The first attempt was rejected during platform creation because `receiveFifo` was unsupported, before ARM execution. Only the already verified current `BlackwallUartAdapter` component was connected with `receiveFifo:true`; no new UART behavior was invented. Before/after model copies and hashes were preserved in captures.

The original task actually read 24 bytes and RX pending became 0. Full SRAM, CPU registers, and TCB were exact immediately before/after input. Pre-reply SRAM/registers were also exact across the three final normal/error-type/incorrect-ID runs. IRQ and peripheral FIFO state intentionally change with input. This is not expanded into universal observer noninterference.

## Actual original consumption path

| Stage | Confirmed original behavior |
| --- | --- |
| UART RX | IRQ entries increase 12→13; original `uart_sync_thread` receives 24 bytes |
| Parser | Original `0x468998`, matches actually generated pending IDs `0x800a` and `0x800b` |
| Normal reply | `0x468ca4` twice → passes `0x107/8byte`, `0x108/12byte` to `0x465c20` |
| Registered dispatch | `0x443a1c` twice, selects actual registry `row+4` callback |
| Wear callback | Executes `0x4b821c` on `worker_thread_0`, returns R0=0 to original caller |
| Slider callback | Executes `0x578ce6` on `worker_thread_1`, returns R0=0 to original caller |
| Slider state | `0x20077568`: 0→5288, `0x2000680c`: 65535→1 |
| Receive completion | Returns to original `0x4fdf3a` caller with same SP/TCB, clears target pending callback/userdata |

Both callbacks and UART receive used their original stacks in Thread mode. Slider helper's actual arguments are role 1/code 4/tick 5288, matching the tick stored in state. Tick 5288 is not represented as physical time or measured delay.

The original callback's local 12 bytes in epilogue capture were also `01000000040000000aa70000`: role 1/code 4/diffX 10/speed 167 actually copied to the callback. Final RAM alone is not claimed to prove every transient write.

## Failure controls

| Reply | Parser/caller return | Normal reply callback | App callback/state change | Target pending |
| --- | --- | --- | --- | --- |
| Normal `0x0a`, matching ID | Confirmed | Twice | Both callbacks, slider state updated | Active callback/userdata cleared |
| `0x0b`, matching ID, valid CRC | Confirmed | Twice | None, initial state preserved | Cleared |
| `0x0a`, unknown IDs `0x900a/0x900b`, valid CRC | Confirmed | Zero | None, initial state preserved | Original request records exact |

All three final runs consumed 24 bytes with CFSR/HFSR, memory violations, and strict guards 0. These controls cover reply type and correlation ID; they do not claim testing all CRC errors, duplicates, or retransmissions in this touch scenario.

## Verification and preservation

- Five actual new M55 runs: epilogue prototype, callback caller return, final RX caller return, error type, and unknown ID. One configuration failure is separate and not counted as an ARM attempt.
- Two isolated original ARM reply-encoder runs and three final native semantic-audit scenarios passed. A saved-audit check assuming pending records always remain in the same slot failed. Original code can remove inactive slots at the end, so the check now verifies removal of active callback/userdata; the failed verifier was preserved. This is neither firmware rerun nor concealment of error.
- Private `touch-peer-reply-research-01` contains builder versions, original reply generation, expected contracts, source-gate records, verifier, and report. Native captures and source inputs are pinned by `touch-peer-reply-manifest.json`.
- All runs are network-free virtual boards and owned process journals are removed. No physical access, writes, flash, subagents, or external publication.

## Additional input tests

`tools/run_active_hud_input.py` reuses the E06 pinned stock24 main/board. It delivers a second scroll report through the verified reloadable IOM5 touch component and GPIO27 input. The explicit virtual scenario waits 400 ms after the first screen and observes 200 ms after input. Virtual time is not a physical performance measurement.

| Run | Changed external input contract | Actual result |
| --- | --- | --- |
| 01 | GPIO low 1 ms | Original re-requested the report while the pin was low and stopped at IOM5 report exhaustion guard |
| 02 | GPIO low 250 µs | Original touch/slider/caller return and service 108 callback, 0 faults/guards; UI effect unconfirmed |
| 03 | 02 + original-expected response 8 to an exactly matching channel 3 request | Additional display synchronization channel 2 request generated, 0 faults/guards; screen unchanged |
| 04 | 03 + existing display response 2 to an exactly matching channel 2 request | Both responses accepted at original UART receive boundary, 0 faults/guards; screen unchanged |

The 250 µs waveform is a declared virtual waveform to deliver one report, not a measurement of the actual touch MCU. The timer overload was added only to the synthetic C# input timer for that run. Existing shared timer source and original firmware were not changed. CPU registers, full SRAM, and virtual time were preserved before and after report injection.

Responses use actual transmit ID and CRC. Aside from existing channel 1 service 107/108 responses, responses are sent only when the two observed request payloads match exactly. Unidentified requests such as channel 4 are left alone. This is an original-based **virtual peer contract**, not execution of the actual opposite glasses binary.

Original stock24 registers the request type 3 callback at `0x469228`. After checking response first byte 8 and existing transmit context, this callback calls the UI type 7 producer at `0x46931e`. `0x466f08` in the peer receive path also constructs response 8. The existing type 2 display response contract reused the [virtual peer reply contract](../display-gpu/ui-peer-reply-ingress-contract.md). Source bytes, disassembly, and main SHA are preserved outside Git.

## Why this was not marked complete

All four runs consumed the report through original touch/slider. In 02–04 the last input tick changed from 5288 to 6346 and the first screen remained. However, there was no visual change. The app1 event 3 callback expected by the audit was not observed either. **The assumption that event 3 is a required UI consumption boundary for this input was not yet verified.** The missing callback alone does not prove there was no internal UI processing.

Execution configuration integrity and semantic verification were separated. Execution checks passed for all four runs, but all E11 semantic checks were preserved as failures. A normal boot frame and source input consumption alone do not advance E11. A no-input control, other input, or older-version integration was not newly claimed complete.

Before arbitrarily increasing response values or time, next check the actual original branches and returns for UI type 7 consumption and type 2 display commands. After choosing input valid for the current screen, verify state/frame differences against no-input and wrong-response controls. Sensor sample consumption E12 is separate.

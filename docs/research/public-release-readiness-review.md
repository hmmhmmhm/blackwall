# Pre-Publication Readiness Review

2026-11-18 · bw-0585. This preliminary, primarily read-only review assumed the initial publication target was the Blackwall emulator repository. It did not change whether or how the project was published. GitHub repository `hmmhmmhm/blackwall` was PRIVATE when checked.

## Work needed before publication

1. **Publication scope and Git cleanup.** At the time, the only Git-tracked file was `docs/.gitkeep`, with 1,592 untracked files not ignored. Inventory the source, documentation, and tests needed to run and validate the emulator rather than adding everything indiscriminately. Decide separately whether existing `web/` firmware-installation research and personal work records belong in published artifacts. This does not imply deleting existing local material.
2. **Sensitive information and proprietary assets.** `.gitignore` excludes `*.bin`, `*.raw`, `*.key`, `local/`, and more, but extensions alone cannot provide complete protection. Inspect text, archives, images, test fixtures, Git history, and future staged diffs. This sample search did not find exact matches for serial/MAC strings from user-supplied photos. That is not a pass of a complete secrets/personal-information audit. Untracked `tests/fixtures/codec-init-wrapper.hex` is 61 bytes of text and described as a synthetic wrapper in tests, but check each fixture's origin before allowing hex files generally. Exclude proprietary firmware, actual device backups, and authentication keys from publication.
3. **Reproducible public path.** The representative run in the then-current [environment guide](../getting-started/fresh-simulator-workspace.md) depended on the existing Mac and 498 pinned files totaling 449,890,129 bytes in a private workspace, plus separate wheels and a pinned Docker image. Distinguish obtainable assets from captures users can generate, and design and verify a public mock/smoke path and optional original-firmware path that outsiders can start. Do not claim another person reproduced it successfully. `setup_simulator.py --help` and `run_display_activation_m55.py --help` did run locally, but that does not constitute an actual run.
4. **Licenses and provenance.** A root project LICENSE was not found. [NOTICE](../../NOTICE.md) and some per-upstream licenses existed. Decide Blackwall's own license and review provenance, required notices, and redistribution permissions for each distributed source, artifact, and fixture. Faceclaw/g2flash GPL obligations and whether proprietary firmware may be distributed need separate investigation; this review alone does not establish legal compliance.
5. **Public documentation's first impression and claims.** The top of the README mixed the latest completion notice with historical `latest` 11/12 and 10/12 statements, creating confusion. On the first screen, distinguish what ran, main reset from Boot ROM, functional models from actual devices, and virtual recovery from physical recovery. Replace personal environment-dependent commands such as `<user-home>/` absolute paths with portable variables/examples, and separate old records as history.
6. **Repeatable verification and safe defaults.** In a clean environment, actually run installation through a minimal scenario, core tests, and error guidance for the publication target. Do not claim installation or full tests passed based only on help text. Separate physical flash/OTA/bootloader writes from the default workflow and explain actual support scope and the lack of physical safety validation. Determine CI scope after deciding dependencies and platforms.

## Recommended sequence

First decide publication scope and distribution rights, then inspect the inventory for sensitive information and provenance. In parallel, define inputs and validation criteria for a minimal demo/smoke path without private assets. Then rewrite the README and installation instructions, reproduce them directly in a separate environment, and review the publication candidate. No external publication or repository-visibility change was performed.

This was a preliminary risk-oriented review, not a legal or security audit of every file. For detailed emulation/bootloader results, see [final bootloader acceptance](../bootloader/bootloader-final-acceptance.md) and [functional acceptance](../architecture/emulator-final-audit.md).

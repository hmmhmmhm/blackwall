# Virtual boot timing and frame collection experiment

bw-0595. At the user's request, a separate profile for pinned stock 2.4 boot/main reads Renode's virtual clock in existing observation callbacks without changing observation points. It retains up to 32 screen captures already read by the GPU. Original firmware, PC, branches, memory, device settings, and existing profile are unchanged. It does not call `SyncTime()`; equal clock values remain ties. Times are virtual clock samples, not claims of physical microsecond precision or performance.

`tools/prepare_timed_boot_profile.py` checks the frozen original strict.cs SHA and each change anchor, then creates new strict/run/profile files in private storage without overwriting existing paths. Default v1 profile remains. Explicitly supply the experimental profile to `tools/blackwall_report.py --profile <profile.json> --scenario normal --output <new private path>`. Input firmware uses the same fixed hash/vector checks. Expected-rejection test is `--scenario unknown-boot-marker`.

The new normal run began at original boot reset, progressed through original main/UI, and recorded three frames and 17 observation points. In this run boot C main was about 98,437 µs, boot manager 5,176,293 µs, stock handoff 5,181,545 µs, and main reset 5,181,546 µs. Three framebuffer observations were 20,619,300 / 20,653,011 / 20,675,300 µs. Inputs, virtual MIPS/cadence, and host polling affect these values, so they can vary by run. The report slider displays captures from the same run by stage. It supplies original raw and a brightness-adjusted version with uniform gain across the full frame.

For identical inputs and virtual device, previous and new normal/unknown-marker boot PCs, order, end PC, fault 0, and UART request/response bytes were compared. Normal handoff CPU context also matched; the new final frame matched endpoint guest SRAM. Frame/event storage overflow was 0 on both sides; times were monotonic and no later than endpoint. Unknown marker stopped at original 0x42e582 boundary with no screen. Existing automatic independent audit and observer-profile audit passed. This comparison does not prove invariance of all guest state or timing. Twenty related unit tests passed and reject reversed timestamps.

Evidence: `private:simulator/timed-boot-native-bw595-01`, `private:simulator/timed-boot-negative-bw595-01`, `private:simulator/timed-boot-observer-bw595/comparison.json`, each `-audit`, and `private:report-bw595-final`. Only three GPU frames are retained; intermediate frames are not generated. This does not verify actual ROM, physical glasses, all peripherals, or arbitrary CFW support.

The subsequent integrated CLI itself also ran anew with `--profile ... --scenario normal`, passing independent audit and report generation. The current tunnel is a separate repeat result in `private:report-bw595-integrated`, with frame times 20,608,649 / 20,642,300 / 20,664,535 µs. Chrome on the actual external tunnel confirmed reset alone at 0 seconds, main reached at 6 seconds, and first/last frame transitions.
